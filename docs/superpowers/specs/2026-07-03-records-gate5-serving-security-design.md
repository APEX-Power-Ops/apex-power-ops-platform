# Records Gate 5 - Serving Security (Ownership Posture + Audit Substrate + Serving Contract)

**Status:** rev 5 (2026-07-03). Rev 2 folded the operator design review + a Codex cross-engine pass + a 3-lens Claude refute; rev 3 folded a 2nd bounded operator review (4 exactness amendments: DROP-OWNED masking guard, auditor DEV-7 drop guard, SET SESSION AUTHORIZATION actor proofs, explicit postgres pre-state); rev 4 folded the P1 that `records_fn_owner` needs schema `USAGE` to reach the `audit_log` it owns (exact-allowlist reframing); rev 5 folds a 3rd operator exactness pass (records_fn_owner schema-`CREATE` denial + schema-owner assert + an adversarial allowlist sweep; Tier-6 durable zero-membership-edge assert). See "Review fold" near the end for the finding-by-finding trace.
**Lane:** `records/gate5-serving-security` off `main @ 03f6c339` (post Gate-3 PR #62).
**Predecessor:** Gate 3 security/RLS (migration `045`; roles `records_api` reader + `records_intake_writer` writer; RLS on all 15 tables; `security_invoker` views; `neta_table_source_links` owner-only). Gate 3 self-admitted its safety rests on an unenforced invariant: *serving connects only as the non-owner app roles, never as owner/postgres*.

**Goal (one sentence):** Convert the Gate-3 backstop from *safe by custody* toward *safe by enforcement* - move records objects off the superuser owner so RLS actually binds the owner, add a metadata-minimal DB-trigger audit trail that makes even owner/direct-SQL mutations visible (with correct actor attribution), and hand Gate 9 a machine-readable serving contract - without building the serving runtime.

**Architecture (2-3 sentences):** Two sequenced authoritative-migration slabs plus a documentation artifact. **5A (ownership posture, mig 046):** reassign every `records.*` object from the superuser `postgres` to a NOLOGIN/NOSUPERUSER/NOBYPASSRLS `records_owner` (with both-direction membership hardening), then `FORCE ROW LEVEL SECURITY` on all 15 tables so RLS binds the owner too. **5B (audit substrate, migs 047-049):** a `records_fn_owner`-owned `SECURITY DEFINER` capture function feeding an append-only, metadata-minimal `records.audit_log` (itself FORCE-RLS'd so the owner does not bypass its INSERT policy) via AFTER-row triggers on the writer-grant table set, readable only by a new read-only `records_auditor`. Plus a checked-in **serving contract** (role -> Supabase boundary + DSN-form inventory) that makes Gate 9 a mechanical rebind. The Check-3 detector stays **dormant**; the runtime startup-identity assertion and comprehensive DSN parser are deferred to the serving-runtime brainstorm / Gate 9, where real config files will exist to test against.

**Tech Stack:** PostgreSQL 17 (dev), Python + psycopg test harness (`run_validation.py` disposable-DB walk), bash `secret-audit.sh` tripwire. Same toolchain and discipline as Gate 3.

## Global Constraints

Every task inherits these (values verbatim from the lane's established discipline):

- **Authoritative migrations, not deltas.** Any grant/role/ownership change REVOKEs/normalizes first, then applies, with **in-migration posture asserts** (`raise exception` on any violated invariant). Mirror the 045 revoke-first + exactness-assert pattern.
- **Reversible `_down` for every migration**, mirroring its up in reverse dependency order; symmetry proven on a disposable DB. For the **NOLOGIN owner roles** (`records_owner`, `records_fn_owner`) the down **fails loud** (raises) if the role survives - it never swallows `dependent_objects_still_exist` as a tolerated NOTICE (that would silently leak a role = a false-green). **Exception:** a password-bearing LOGIN role (`records_auditor`) follows the DEV-7 guard (revoke grants; drop only if passwordless/harness-created; RETAIN with a NOTICE if password-bearing) so a down on a persistent cluster never destroys an operator-provisioned credential. Any `DROP OWNED BY` is preceded by an assert that the role owns ZERO records objects (see 046_down) so it can only clear ACL residue, never delete a missed object.
- **ASCII-only added lines** (no U+2014 em-dashes etc.).
- **Tests run against a DISPOSABLE dev DB only** (`records_val_*` / `records_spike_*` generated names); **NEVER `records_dev`** (the harness `guard_target` refuses it) and **NEVER prod Supabase** (Gate-3 AC7 stands - nothing in this gate is applied to prod).
- **Role/credential discipline.** No migration sets a password. `records_owner` and `records_fn_owner` are **NOLOGIN** (pure object owners, never connection identities). `records_auditor` is **LOGIN with NO inline password** (provisioned out-of-band, Vault-first); its read path is proven in the harness via `SET ROLE records_auditor` from the superuser session (direct-connect auth is out of scope), consistent with how `records_api`/`records_intake_writer` are exercised today.
- **Value-silent detectors.** Any secret/DSN tripwire prints `file:line + rule name` only, never a value.
- **`TO <named-role>` policy idiom** on every new policy, so Gate 9's rebind to Supabase boundaries stays a mechanical find/replace.
- **Audit is metadata-minimal by default** (operator ruling, 2026-07-03): rows carry table, pk, operation, the **mutating actor identity + the definer role**, txid, timestamp, and changed-column **NAMES** - **NOT full before/after row values and NOT a content hash of the row.** A plain hash of low-cardinality columns is itself a reversible value oracle; any content digest requires explicit operator ratification AND an HMAC keyed by a secret held outside `audit_log`.
- **Honest scope claim.** This gate closes the NON-superuser-owner RLS-bypass. It does NOT close `postgres`-superuser or Supabase `service_role` bypass - those remain custody + detector + a startup-identity assertion deferred to the first real serving process. The gate's writeup must say "much safer + detectable," never "safe by enforcement" unqualified.

## Feasibility grounding (pre-build spike, 2026-07-03)

A throwaway spike built the full 001-045 schema on a disposable DB and proved the 5A mechanism empirically (Appendix A). Verified: all 15 tables + 2 views + 1 function + the `records` schema are owned by `postgres` (`superuser=true, bypassrls=true`); zero sequences (uuid PKs). Explicit per-object `ALTER OWNER` to a non-superuser `records_owner` reassigns all 18 objects + schema + function with **0 stragglers** and reverses with **0 stragglers**. On a FORCEd `neta_tables` (88 rows): superuser sees 88, `records_owner` sees **0**, `records_api` sees 88 (its policy); the unFORCEd contrast table lets the owner see all rows; an owner-path INSERT is **blocked by RLS**. Verdict: **GO** - feasible, clean, reversible.

**Caveat carried into rev 2:** the spike exercised only the *pure-ownership* reversal (records_owner held no grants). A refute pass verified live that `REASSIGN OWNED ... TO postgres` does NOT let `DROP ROLE` succeed if the role holds ANY grant (ACL entries are `pg_shdepend` deptype='a', which reassign-owned never clears). So `records_owner` is kept a **pure owner with zero grants** (asserted; it is also the schema owner, so it has schema USAGE implicitly). **Amended rev 4:** `records_fn_owner` is NOT zero-grant - its `SECURITY DEFINER` capture function must reach `records.audit_log`, and object ownership does not convey schema USAGE (045 revoked PUBLIC usage on `records`), so 048 grants it `USAGE ON SCHEMA records`. It is therefore held to an **EXACT ALLOWLIST** (schema USAGE only; no explicit table/function grant beyond ownership; no membership; no login/super/bypass), asserted in 048 + Tier 6. **Amended rev 5 (adversarial allowlist audit):** the allowlist is ENFORCED by a single `pg_shdepend` `deptype='a'` exclusivity assert (the ONLY permitted ACL edge is `USAGE` on `records` in this DB) plus explicit-USAGE / CREATE-deny / PUBLIC-holds-no-schema-privilege / schema-owner=`records_owner` / schema-exists gates - because the earlier per-object `relacl`/`proacl` scans were structurally blind to cross-schema grants, column/type/domain grants, DATABASE-level grants, default privileges (`pg_default_acl`, incl. the `defaclnamespace=0` case), and shared-object grants (all empirically confirmed false-green on PG17). Ownership is `deptype='o'`, so a self-GRANT on the owned `audit_log` never trips it. Tier 6 re-runs the identical block. The `_down` still uses `DROP OWNED BY` + fail-loud - `DROP OWNED BY` also revokes that USAGE grant, so `DROP ROLE` still succeeds (safe because these roles are NOLOGIN, single-DB, no cross-DB CONNECT - unlike the LOGIN app roles that forced 045_down to avoid DROP OWNED).

Two consequences the spike surfaced (folded below): (1) ownership hygiene is an **ongoing invariant** - future migrations run as `postgres` and would create superuser-owned objects again, so a drift tripwire is required; (2) `records_owner` must **never be a DML identity** (FORCE RLS blocks its writes), lightly tensioning Gate-3 D9's "maintenance/owner path" (resolved: bulk import runs as the custody-controlled superuser path - which is now audited - or as a writer role with a policy; never as plain records_owner).

## Decisions

| # | Decision | Ruling |
|---|----------|--------|
| G5-D1 | Owner-path treatment | **Move all `records.*` objects to a non-superuser/non-BYPASSRLS `records_owner` + FORCE RLS** (mig 046). Operator-ratified in-DB hardening path. Residual `postgres`-superuser / `service_role` bypass stays custody + detector + startup-assertion (deferred). |
| G5-D2 | `records_owner` shape + membership | **NOLOGIN, NOSUPERUSER, NOBYPASSRLS, holds ZERO privilege grants** (pure object owner). **Both-direction role membership is revoked + asserted** (no LOGIN role may inherit or `SET ROLE` into `records_owner`): because it owns the schema/tables, membership would be a DDL-escalation path. Tier 6 proves `SET ROLE records_owner` is denied from the app roles and a rogue role. |
| G5-D3 | FORCE RLS scope | **All 15 records tables.** Reference tables keep their `USING(true)` read policies `TO` the app roles (app reads unaffected); the owner now sees 0 without a policy. `neta_table_source_links` stays deny-by-default. Migrations run as `postgres` (superuser bypasses FORCE - verified), so migration DDL/DML is unaffected. |
| G5-D4 | Ongoing ownership hygiene | **Harness Tier-6 posture assert that FAILS if any `records.*` table/view/matview/sequence/function is owned by a `rolsuper` OR `rolbypassrls` role** (future-migration drift). Plus an authoring discipline note (new records objects `ALTER OWNER TO records_owner` / audit objects to `records_fn_owner`). |
| G5-D5 | Audit mechanism + row-shape contract | **DB triggers.** AFTER INSERT/UPDATE/DELETE FOR EACH ROW on the writer-grant table set, calling ONE shared `records.fn_audit_capture()`. The 6 writable tables have **6 distinct single-column PK names** (`asset_id`, `form_submission_id`, `field_value_id`, `person_id`, `pm_event_id`, `pm_schedule_id`; none is `id`), so the PK column name is passed per-table via `CREATE TRIGGER ... EXECUTE FUNCTION fn_audit_capture('<pk_col>')`; the function reads `rec := CASE WHEN TG_OP='DELETE' THEN OLD ELSE NEW END` and `row_pk := to_jsonb(rec) ->> TG_ARGV[0]`; `changed_columns` is computed only on UPDATE (OLD vs NEW). Reuses the `records.fn_set_updated_at` (mig 004) shared-function precedent. |
| G5-D6 | Audit content (metadata-minimal) | Columns: `audit_id` (bigint identity PK); `event_at` (`clock_timestamp()`); `action` (insert/update/delete CHECK); `table_name`; `row_pk` (text, per D5); **`actor_role`** = the MUTATING session identity (`session_user`) - **NOT `current_user`**, because inside a SECURITY DEFINER trigger `current_user` is the definer `records_fn_owner`; `session_user` is unaffected by SECURITY DEFINER and names the connected login/serving identity; **`definer_role`** (`current_user`) recorded separately for transparency; **`actor_is_superuser`** derived from the session identity (`select rolsuper from pg_roles where rolname = session_user`), not the definer; `txid` (`txid_current()`); `application_name`; `client_addr` (`inet_client_addr()`); `changed_columns` (text[] of NAMES, UPDATE only, **EXCLUDING the trigger-maintained `updated_at`** - the BEFORE `fn_set_updated_at` sets `updated_at := now()` on every update, so it is deterministic maintenance noise, not a caller-intent change; `changed_columns` reflects caller intent, ordered deterministically via `array_agg(o.key order by o.key)`; Codex P2-2 ruling 2026-07-03); **`app_actor`** (nullable, from `SET LOCAL records.app_actor`) - **bounded by a length cap + identity-token CHECK in `fn_audit_capture` and treated as UNTRUSTED caller free-text** (a writer must not be able to smuggle a value into the audit trail through it). **NO before/after row value images and NO content `row_hash`** (a plain md5 of low-cardinality `form_field_values` columns is a reversible value oracle for an auditor RLS-blocked from the row; `changed_columns` NAMES already answer "what changed"). |
| G5-D7 | source_links audit + DRM boundary | **EXCLUDE `neta_table_source_links` from audit triggers**, and assert its trigger set is empty. **DRM boundary (stated explicitly for Gate 9):** the `source_links` boundary protects LINEAGE/PROVENANCE (source repo/path/locator), NOT the NETA acceptance *tolerance numeric values*, which are per-instance resolved windows (the R-A design) held as first-class record content in `form_field_values` and are intentionally auditable. With metadata-minimal audit (no row images, no content hash), no tolerance VALUE reaches `audit_log` regardless. If a future ruling makes tolerance values source-protected, D7's single-table exclusion is insufficient and a `form_field_values` column-allowlist is required (flagged, not built). |
| G5-D8 | `records_auditor` role | **LOGIN (no inline password, out-of-band), read-only, scoped to `records.audit_log` ONLY.** It does **not** get SELECT on the operational or reference tables: Gate-3 RLS policies name only the app roles, so a raw grant returns zero rows anyway, and a new human-facing read path over operational data is an unnecessary surface. Correlation to live rows is deferred. AC asserts `records_auditor` has **NO grant AND NO applicable policy** on `neta_table_source_links` or any operational/reference table. Approver-write + review decision table + workflow deferred. |
| G5-D9 | audit_log RLS/grants | RLS enabled **AND `FORCE ROW LEVEL SECURITY`** (so the owner `records_fn_owner` is itself subject to the INSERT policy - without FORCE, the owner-invoked SECURITY DEFINER function bypasses RLS and the `INSERT ... TO records_fn_owner` policy is a no-op = the exact false-green this gate targets). **SELECT policy `TO records_auditor`; INSERT policy `TO records_fn_owner`;** NO app-role grant/policy; append-only (no UPDATE/DELETE policy for anyone). Owned by `records_fn_owner`. |
| G5-D10 | Definer-function safety | `records.fn_audit_capture()` is **SECURITY DEFINER, owned by `records_fn_owner` (NOLOGIN/NOSUPER/NOBYPASSRLS), `SET search_path = pg_catalog, records` pinned**. In-migration (048): `ALTER FUNCTION ... OWNER TO records_fn_owner` explicitly + assert `proowner = records_fn_owner` + assert owner `rolbypassrls=false AND rolsuper=false` + assert `proconfig` pins search_path. These **three run-time asserts are load-bearing as a SET** and are **re-checked durably every CI run by Tier 6** (a later `DROP FUNCTION` + `CREATE FUNCTION` recreates it postgres-owned, or drops the search_path pin - a one-shot 048 assert does not catch that). **Rev 4:** the definer runs as `records_fn_owner`, which OWNS `audit_log` but still needs `USAGE ON SCHEMA records` to reach it (ownership != schema usage; 045 revoked PUBLIC usage) - 048 grants exactly that and asserts the exact allowlist (USAGE only, no explicit table/function grant beyond ownership); without the grant the capture fails `permission denied for schema records` before RLS. |
| G5-D11 | Serving contract | `reference/records/SERVING_CONTRACT.yaml` + companion `.md`: **each role classified `connects: true|false` + `supabase_target`** (`records_api`/`records_intake_writer`/`records_auditor` -> connecting logins mapped to their Supabase boundary; `records_owner`/`records_fn_owner` -> `connects:false`, owner-only, no DSN), plus the **045/048** policy names bound to each and the DSN-form inventory the eventual serving config is expected to use. Gate 9 consumes it mechanically. **Check-3 stays dormant** (`RECORDS_SERVING_GLOBS` unset) - an honest SKIP, not an armed-but-empty PASS. |
| G5-D12 | Tier-6 posture asserts | Value-silent in-DB (harness Tier 6): (a) `records_owner`/`records_fn_owner`/`records_auditor` all `rolsuper=false AND rolbypassrls=false` (+ correct login flags + no createdb/createrole/replication); (b) no `records.*` object owned by a super/bypassrls role (counted across pg_class + pg_proc + pg_namespace); (c) `fn_audit_capture` is `proowner=records_fn_owner AND prosecdef=true AND proconfig` pins search_path + no PUBLIC EXECUTE, **and `records_fn_owner` passes the exact-allowlist block: schema exists + owned by `records_owner`, explicit `USAGE` present, `CREATE` denied, PUBLIC holds no schema privilege, and a single `pg_shdepend` `deptype='a'` edge (USAGE on `records`) with no cross-schema/column/type/default-priv/database/shared-object grant**; (d) **zero `pg_auth_members` edges (either direction) touching `records_owner`/`records_fn_owner`/`records_auditor`** (a durable no-membership-drift proof; the in-migration 046/047 checks are point-in-time) AND `SET ROLE records_owner`/`records_fn_owner` denied from the app roles and a rogue role; (e) the audit-trigger table set **equals the writer-grant table set** derived from `information_schema.role_column_grants` for `records_intake_writer` (INSERT/UPDATE) - not a hardcoded list, so a future writable table cannot silently drift out of audit; (f) the FORCE-RLS negative control (definer insert RAISES with the INSERT policy dropped, inside a rolled-back savepoint). |

## Migration + harness shape

Authoritative migrations `046-049`, each with a reversible `_down`, following the 045 idiom. All applied only to disposable dev DBs in this gate.

- **`046_records_ownership.sql`** - **first assert the expected pre-state: every `records.*` object + the schema is owned by `postgres`** (fail if not - the build target is post-Gate-3 main, whose owner is `postgres`; this pins the down's target owner rather than capturing a prior-owner map); create `records_owner` (NOLOGIN NOSUPER NOBYPASSRLS, guarded); both-direction membership revoke + assert; deterministic explicit `ALTER OWNER` of every `records.*` table/view/matview/sequence/function + the schema to `records_owner` (a `do`-block over `pg_class`/`pg_proc`, NOT `REASSIGN OWNED BY postgres`); `FORCE ROW LEVEL SECURITY` on all 15 tables; asserts: (a) 0 records objects not owned by `records_owner`; (b) `records_owner` non-super/non-bypassrls; (c) all 15 `relforcerowsecurity`; (d) `records_owner` holds zero privilege grants (`pg_shdepend` has no deptype='a' rows for it); (e) no LOGIN role is a member of `records_owner`. **`046_down`:** `NO FORCE` on the 15; reassign every object **explicitly back to `postgres`**; **then ASSERT zero `records.*` objects remain owned by `records_owner` - this guard is REQUIRED before `DROP OWNED BY`: a `DROP OWNED BY` on an incomplete reassign would silently DELETE any missed object and let the role drop cleanly, a false-green symmetry proof (and data loss)**; only then `DROP OWNED BY records_owner` (now provably clears ACL residue only, deletes nothing) + `DROP ROLE records_owner`; **RAISE if the role survives.**
- **`047_records_audit_roles.sql`** - `records_fn_owner` (NOLOGIN NOSUPER NOBYPASSRLS) + `records_auditor` (LOGIN, no inline password). Both-direction membership hardening on both. Authoritative revoke-first; auditor gets NO operational/reference grant here (its audit_log read is granted via policy in 048). Asserts: both roles non-super/non-bypassrls (+ correct login flags + no createdb/createrole/replication), zero-grant for fn_owner AT 047 (its single schema-USAGE grant is added in 048; 048 + Tier 6 assert the exact allowlist), and zero membership edges either-direction for both audit roles. **`047_down` uses asymmetric drop discipline:** `records_fn_owner` (NOLOGIN, harness-created, no credential) = zero-owned assert + `DROP OWNED BY` + `DROP ROLE` + **RAISE-on-survive** (as 046_down); `records_auditor` (LOGIN, password provisioned out-of-band) = **DEV-7 guard mirroring 045_down** - revoke its DB grants, and `DROP ROLE` ONLY if it is passwordless/harness-created, otherwise RETAIN it with a NOTICE (never RAISE), so a down on a persistent cluster never destroys an operator-provisioned credential.
- **`048_records_audit_log.sql`** - `records.audit_log` (owned by `records_fn_owner`); BRIN on `event_at`, btree on `(table_name, row_pk)`; partition-key + retention posture in a COMMENT (no machinery); RLS enabled **+ FORCE RLS**; SELECT policy `TO records_auditor`, INSERT policy `TO records_fn_owner`; NO app-role grant/policy; **`grant usage on schema records to records_fn_owner`** (the definer must reach `audit_log`) + **to `records_auditor`** (or its SELECT is unreachable); `fn_audit_capture()` SECURITY DEFINER owned by `records_fn_owner`, search_path pinned, `REVOKE EXECUTE ... FROM PUBLIC`; the three load-bearing asserts (G5-D10) + FORCE-RLS + no-PUBLIC-execute + the `records_fn_owner` exact-allowlist assert (USAGE only, no explicit table/function grant beyond ownership). `048_down` revokes both schema-USAGE grants + drops function + table + policies.
- **`049_records_audit_triggers.sql`** - AFTER I/U/D FOR EACH ROW trigger on each writer-grant table, `EXECUTE FUNCTION fn_audit_capture('<pk_col>')` with that table's PK name; assert the trigger set for this function **equals** the derived writer-grant set (not audit_log - recursion guard; not source_links - G5-D7). `049_down` drops the triggers.
- **Harness (`run_validation.py`) Tier 6** - proves: ownership (all records objects non-super/non-bypassrls owned; FORCE-RLS teeth: owner 0 / app rows / owner-write blocked); membership (`SET ROLE` denial per G5-D12d); audit (INSERT-as-writer, exercised via `SET SESSION AUTHORIZATION records_intake_writer`, lands exactly one metadata-minimal row with `actor_role=records_intake_writer`, NOT the definer; a superuser/direct-SQL UPDATE and DELETE each land a row with `actor_role`=the session login + `actor_is_superuser=true`, `row_pk` non-null on delete; no value-image/content-hash column; `source_links` has no trigger; the definer three-assert SET + the FORCE-RLS negative control: with the INSERT policy dropped the capture RAISES); isolation (auditor reads audit_log via SET ROLE; app roles cannot; auditor has no source_links/operational access); the writer-grant-derived trigger-set equality. Plus `parse_tiers` extended to `{0..6}` with the full-set guard + unit tests.
- **Serving contract** - `reference/records/SERVING_CONTRACT.{yaml,md}` per G5-D11. No code consumes it in this gate.
- **CI** - `records-ci.yml` `--require-db` runs the full ladder incl. Tier 6; the AC8 fixture step stays.

**PR strategy (plan-phase):** 5A (046) and 5B (047-049 + contract) may land as two PRs for reviewability, or one - the plan decides. 5A ships first; its ownership assert is scoped "all owned by records_owner" (valid at 046, before audit objects exist), while the cumulative Tier-6 invariant is "owned by a non-super/non-bypassrls role" (valid always, allows records_fn_owner).

## Acceptance Criteria

- **AC1 (ownership + reversible).** After 046, every `records.*` object + the schema is owned by `records_owner`; `046_down` reassigns back, `DROP OWNED BY` + `DROP ROLE` succeeds, and RAISES if the role survives. 0 stragglers each direction; role actually dropped (test).
- **AC2 (FORCE teeth).** All 15 tables `FORCE ROW LEVEL SECURITY`; a non-superuser owner sees 0 rows on a seeded table with no owner policy; app roles see their policy rows; an owner-path INSERT is RLS-blocked (test).
- **AC3 (ownership-drift).** Tier-6 assert FAILS when any `records.*` object is owned by a `rolsuper` OR `rolbypassrls` role (plant a superuser-owned object -> fail; clean -> pass).
- **AC4 (audit capture).** Triggers exist on exactly the **writer-grant table set** (derived from 045's grants, not hardcoded), and not on `audit_log` or `source_links`. Writer INSERT and UPDATE each yield one audit row; DELETE trigger coverage is structural and is exercised via a **maintenance/superuser DELETE** (the writer has NO DELETE per Gate 3), which yields one audit row with `row_pk` non-null (test).
- **AC5 (metadata-minimal).** `audit_log` has NO before/after value-image column AND NO content `row_hash` column; `actor_role` = the mutating session identity; no audit row contains a source/operational data value (test asserts the column set + inspects captured rows).
- **AC6 (definer false-green guard).** `fn_audit_capture` is SECURITY DEFINER owned by `records_fn_owner`; the three asserts (proowner=records_fn_owner; owner rolbypassrls=false AND rolsuper=false; insert-as-writer lands) all present in one test path; `audit_log` is FORCE RLS; **negative control:** with the `INSERT ... TO records_fn_owner` policy dropped, the capture RAISES (row violates RLS) - proving the landing is due to the policy, not owner bypass; the function is NOT `postgres`-owned.
- **AC7 (audit isolation).** `records_auditor` (via SET ROLE) reads `audit_log`; `records_api`/`records_intake_writer` can neither read nor write it; `records_auditor` has NO grant AND no applicable policy on `neta_table_source_links` or any operational/reference table (test via session authorization).
- **AC8 (Tier-6 posture).** Value-silent: the three owner/fn_owner/auditor roles are non-super + non-bypassrls; `fn_audit_capture` prosecdef+proconfig durable re-check passes; `SET ROLE` into the owner roles is denied from app/rogue roles.
- **AC9 (serving contract).** `SERVING_CONTRACT.{yaml,md}` present + machine-readable; every connecting role has a `supabase_target`, every NOLOGIN owner is flagged `connects:false`/owner-only/no-DSN; Check-3 remains dormant (honest SKIP), NOT armed.
- **AC10 (discipline).** Every migration has a reversible `_down` (symmetry proven, fail-loud on role survival); ASCII-only added lines; all tests on disposable DBs; nothing applied to prod Supabase.
- **AC11 (actor attribution).** A writer INSERT records `actor_role=records_intake_writer` and `definer_role=records_fn_owner` (NOT actor_role=the definer); a superuser/direct-SQL mutation records `actor_role`=the session login + `actor_is_superuser=true` - proving the owner/direct-SQL path is captured with correct attribution (the whole point of the trail). **The writer mutation MUST be exercised with `SET SESSION AUTHORIZATION records_intake_writer`** (which sets `session_user`), NOT `SET ROLE` (which leaves `session_user=postgres` and would falsely attribute the row to postgres); this mirrors the Gate-3 Tier-5 `SET SESSION AUTHORIZATION` app-role proof. Auditor READ checks (AC7) may use `SET ROLE` (they do not depend on `session_user`).

## Non-goals (explicitly deferred)

- **Serving runtime** (tablet entry UI, scripted pass/fail calc, PDF report-gen) - separate flagship product arc.
- **Thin real serving consumer** + a live `assert_serving_identity()` **startup guard** + **arming Check-3** + **broadening the DSN parser** - all need real serving config files, which are born with the runtime / Gate 9. Gate 5 hands them the contract + audit schema + the dormant Check-3 as ready inputs.
